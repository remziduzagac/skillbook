# Scope

What belongs in skillbook, and the bar a change must clear.

## What belongs

- The person's skills for keeping projects well: blueprint, greenrepo, and the skills they rely on.
- Skills used in every project. A skill that belongs to one project stays in that project.

Each set is installed as one skill; its files under `references/` are guides. Essentials reads its six main guides on every request and uses its guide map to choose further guides. It names no other set. Other sets may build on essentials; essentials uses whatever skills the agent has available for the work itself, with judgment where nothing fits.

## The bar for a change

1. **An observed failure.** The change answers something that went wrong in a real session: the skill misread a situation, skipped a step, loaded the wrong guide, or produced something the person had to undo. A hypothetical improvement does not clear this part.
2. **It fits the design.** It matches nothing already rejected in [.out-of-scope/](.out-of-scope/README.md), and it is not a per-person setting, a branch for one agent harness, or a tweak to suit one workflow. Personal preferences belong in the person's own steering files.

Size does not matter: a one-word fix and a rewrite face the same bar.

## New skills

A behaviour that can be composed from existing skills and guides does not get a new skill. Every skill is permanent upkeep: it stays in step with the others, its docs page, and the manifest.

## Rejected ideas

Each file in [.out-of-scope/](.out-of-scope/README.md) records one rejected idea and why, so a repeated request is answered with a link.
