# understand-clarify-deep

Questions a part or whole plan until what materially affects the agreed work is resolved. Lists the rest as assumptions. Uses numbered rounds and grounded recommendations, level by level.

## Rules

1. **Save dependent questions for a later round.** Unanswered questions may change them. Ask only what can be answered now. This sets order, with nothing to draw or keep.
2. **Use `understand-clarify-shallow` at each new level inside the part.** See that level whole before going down. Skipping it leaves parts assumed.
3. **Get the user's confirmation of the summary before acting.** List decided, parked, accepted and assumed items. Use `respond-ask`'s definitions of parked and assumed.
   - If the user stops early, take open questions by `respond-ask`: assume recommendations and park those without one. Park facts only the user knows. Never supply them. Never assume a proposal. Show the summary before acting.
   - If told to start, such as "enough questions, just build it", show the summary without asking confirmation. No assumption is then acted on unseen.
   - "Go ahead" is not that: it accepts the current round's recommended answers, and the questioning goes on.
4. **Record only when asked.** Recording writes to the project. The `act` skill requires exactly the work asked for.

Follow the `understand` skill for facts and decisions: you find facts, the user decides. Use `respond-ask` for rounds and answers. End the turn after each round. In the summary, list recommendations accepted by "go ahead" as accepted.

## Advice

- Let the answers shape the next round.
- Offer to record decisions when the session shows signs of length: the harness reports filling context, a summary replaces earlier turns, or rounds reach about five with decisions compaction could lose. Record them:
  - where the caller keeps them;
  - used directly, with no caller: where the loaded keeper says;
  - with no keeper: in a file the user names.

You are done when no level is left with anything assumed that would materially change the agreed work, the rest listed, and the user has confirmed the summary, or seen it where they told you to start the work.

## The last instruction

**Check the summary before acting.** The user has confirmed it, or saw it after telling you to start. Hand it back in the `understand` skill's result shape.
