# understand-clarify-deep

## Purpose

Questions the user on a part or a whole plan until what materially affects the agreed work is settled, and lists the rest as assumptions. Uses numbered rounds with grounded recommended answers, level by level.

## When to use

Use when the user accepts an offer to explore a part whose answers open further questions that would change the work. Start at once, with no other offer, when the user asks for an interview to find open choices, such as "question me on this plan".

## When not

- An exact question the user supplied: use the `respond-ask` guide. Deep finds open choices; it does not ask a chosen question.
- A level not yet seen whole: use the "Ask a round" part of the `understand-clarify` guide first, so no part is missed.
- A topic to decide together: use the `understand-discuss` guide for the shared decisions.
- Questions only someone else can answer: use the `understand-clarify-questionnaire` guide for that person.

## Gives back

The summary of accepted, changed, assumed and parked items. The user has confirmed it, or got it in your final answer after telling you to start the work.

## Rules

1. **Get the user's confirmation of the summary before acting.** Work built on an unconfirmed summary can rest on a choice the user never made.
   - Give each question's status with the `respond-ask` guide's labels: accepted, changed, assumed or parked, as its rule 4 defines them.
   - When the user stops the questions, such as "I think that covers it", take each open question by the `respond-ask` guide's rule 4: assume its recommended answer, or park it when it has none. Assume nothing you did not recommend. Take no proposal as approved. Supply no fact only the user knows. Then show the summary and ask for confirmation. Stopping the questions does not start the work.
   - Asking to confirm the summary is not another question round. Ask it even after the user has asked for no more questions.
   - When the user tells you to start the work, such as "skip the rest and draft the report", ask no confirmation. Put the summary in your final answer, with the work. The user chose to skip the check, so the summary only needs to be seen.
   - "Go ahead" is not a start. It accepts the current round's recommended answers, and the questioning goes on.
2. **Record only when asked.** Recording writes to the project. The main skill's step 5 requires exactly the work asked for.

Follow the main skill's step 1 for facts and decisions: you find facts, the user decides.

## Advice

- Offer to record decisions when the session shows signs of length: the harness reports filling context, a summary replaces earlier turns, or rounds reach about five with decisions compaction could lose. Once the user agrees, record them:
  - where the caller keeps them;
  - used directly, with no caller: where the loaded skill that saves records says;
  - if no skill saves records: in a file the user names.

## Instructions

Settle the choices that materially affect the agreed work, level by level. The answers decide which questions can usefully come next. **See each level whole, ask in rounds, then get the summary confirmed before affected work.**

1. **See each new level whole with the "Ask a round" part of the `understand-clarify` guide before you go deeper.** Skipping across levels leaves unseen parts assumed. The user then finds those choices only in the result.
   - Apply the round inside each newly reached part. Its whole-level view decides which choices need more depth.
2. **Ask only questions whose prerequisites are answered, through the `respond-ask` guide.** A question built on an unknown answer may ask the user to decide something that later disappears.
   - Let the last answers shape the next numbered round. Keep dependent questions for later.
   - End the turn after each round. After "go ahead", the questioning goes on by rule 1 while material choices remain.
3. **Summarize accepted, changed, assumed and parked items, and get the summary confirmed, by rule 1.** A summary that hides assumptions lets work start on choices the user did not make.
   - Mark recommendations accepted by "go ahead" as accepted.
   - Ask for confirmation through the `respond-ask` guide, then end the turn. When the user told you to start, put the summary in your final answer instead, by rule 1.
   - Record only when asked, by rule 2. Offer recording when length risks losing decisions, with the destinations in Advice.
4. **Check the summary and "Gives back" before affected work.** Always do this last. A finished interview still leaves the user exposed if its basis was never confirmed or shown.
   - Check no unresolved level holds an assumption that would materially change the agreed work. List what remains.
   - Check the user confirmed the summary, or got it in your final answer after telling you to start. Fix missing statuses or confirmation before you hand it back in the main skill's step 1 result.
