# understand-clarify-deep

Questions a part, or a whole plan, until what materially affects the agreed work is resolved, the rest listed as assumptions: numbered rounds, each question with a recommended answer where there is a basis, going down level by level.

## Rules

1. **A question that depends on an unanswered one waits** for a later round, because that answer may change it. Each round asks what can be answered now. This is an order to ask in, with nothing to draw or keep.
2. **Level by level:** at each new level inside the part, first see that level whole through `understand-clarify-shallow`, then go down. A skipped level leaves its parts assumed.
3. **The user confirms the summary before anything is acted on.** The summary lists what is decided, parked, accepted and assumed, with parked and assumed as `respond-ask` defines them.
   - If the user stops early, take each open question as `respond-ask` says: assumed with its recommended answer, or parked where it has none. A fact only the user knows stays parked; never supply it. A proposal is never assumed. Show the summary before acting.
   - Where the user tells you to start the work, such as "enough questions, just build it", showing the summary is enough, because nothing assumed is then acted on unseen.
   - "Go ahead" is not that: it accepts the current round's recommended answers, and the questioning goes on.
4. **Never record unasked:** recording writes to the project, and the `act` skill's rule is to do exactly what was asked.

Facts and decisions follow the `understand` skill's rules: you find the facts, and the decisions are the user's. Put rounds and take answers as `respond-ask` says. After each round, end the turn, as `respond-ask` says. In the summary, list as accepted the recommended answers that "go ahead" accepted before the end.

## Advice

- Let the answers shape the next round.
- Offer to record the decisions so far when you see a sign that the session is long: the harness says its context is filling up, a summary has replaced earlier turns, or the rounds reach about five, each adding decisions that compaction could lose. Where to record them:
  - where the caller keeps them;
  - used directly, with no caller: where the loaded keeper says;
  - with no keeper: in a file the user names.

You are done when no level is left with anything assumed that would materially change the agreed work, the rest listed, and the user has confirmed the summary, or seen it where they told you to start the work.

## The last instruction

Before you act on anything: the user has confirmed the summary, or you showed it where they told you to start the work, and you hand it back in the `understand` skill's result shape.
