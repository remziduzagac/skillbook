# understand-clarify-deep

## Purpose

Questions a part or whole plan until what materially affects the agreed work is resolved, listing the rest as assumptions. Uses numbered rounds and grounded recommendations, level by level.

## When to use

Use when the user accepts an offer to explore a part whose answers open further questions that would change the work. Start at once, without another offer, when the user asks for an interview to find open choices. Example: “question me on this plan”.

## When not

- An exact question supplied by the user: use the `respond-ask` guide. Deep finds open choices rather than asking a chosen question.
- A level not yet seen whole: use the `understand-clarify-shallow` guide first so parts are not missed.
- A topic to decide together: use the `understand-discuss` guide for the shared decisions.
- Questions only someone else can answer: use the `understand-clarify-questionnaire` guide for that person.

## Gives back

The summary of decided, parked, accepted and assumed items. The user has confirmed it, or seen it after telling you to start the work.

## Rules

1. **Get the user's confirmation of the summary before acting.** List decided, parked, accepted and assumed items. Use the `respond-ask` guide's definitions of parked and assumed.
   - If the user stops early, take open questions by the `respond-ask` guide: assume recommendations and park those without one. Park facts only the user knows. Never supply them. Never assume a proposal. Show the summary before acting.
   - If told to start, such as "enough questions, just build it", show the summary without asking confirmation. No assumption is then acted on unseen.
   - "Go ahead" is not that: it accepts the current round's recommended answers, and the questioning goes on.
2. **Record only when asked.** Recording writes to the project. The `act` guide requires exactly the work asked for.

Follow the `understand` guide for facts and decisions: you find facts, the user decides.

## Advice

- Let the answers shape the next round.
- Offer to record decisions when the session shows signs of length: the harness reports filling context, a summary replaces earlier turns, or rounds reach about five with decisions compaction could lose. Where to record them, once the user agrees:
  - where the caller keeps them;
  - used directly, with no caller: where the loaded skill that saves records says;
  - if no skill saves records: in a file the user names.

## Instructions

Resolve the choices that materially affect the agreed work, level by level. Answers determine which questions can usefully come next. **See each level whole, ask in rounds, then get the summary confirmed before affected work.**

1. **See each new level whole with the `understand-clarify-shallow` guide before descending.** Skipping across levels leaves unseen parts assumed, and the user discovers those choices only in the result.
   - Apply shallow inside each newly reached part. Its whole-level view decides which choices need further depth.
2. **Ask only questions whose prerequisites are answered, through the `respond-ask` guide.** A question built on an unknown answer may ask the user to decide something that later disappears.
   - Let the last answers shape the next numbered round. Keep dependent questions for later.
   - End the turn after each round. “Go ahead” accepts that round's recommended answers; questioning continues where material choices remain.
3. **Summarize decided, parked, accepted and assumed items under rule 1.** A summary that hides assumptions lets work start on choices the user did not make.
   - Use the `respond-ask` guide's meanings of parked and assumed. Mark recommendations accepted by “go ahead” as accepted.
   - When the user stops early, assume recommendations, park questions without one and park facts only they know. Never assume proposal approval.
   - Show the summary and ask for confirmation through the `respond-ask` guide. End the turn before acting. If the user told you to start, show it without asking again, by rule 1.
   - Record only when asked, by rule 2. Offer recording when length risks losing decisions, using the destinations in Advice.
4. **Check the summary and “Gives back” before affected work.** Always do this last. A finished interview still leaves the user exposed if its basis was never confirmed or shown.
   - Check no unresolved level holds an assumption that would materially change the agreed work. List what remains.
   - Check the user confirmed the summary, or saw it after telling you to start. Fix missing statuses or confirmation before handing it back in the `understand` guide's result shape.
