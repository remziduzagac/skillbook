# understand-argue

Makes the strongest honest case for a position, labelled one-sided.

## Rules

1. **Give the precise position through `understand-frame`.** Give its claim, goal and constraints. A vague position can be defended against anything and proves nothing.
   - Get the audience from the caller or known context.
   - **If an unknown audience would change the case, ask through `understand-clarify`.** Then end the turn.
   - If the unknown audience would not change the case, mark it unknown. Invent no audience concerns.
2. **Support each reason with evidence or mark it as an assumption.** Give its source, strength and limits. A reason from memory counts as unchecked until a source confirms it. State nothing false or overstated. False premises fail when relied on.
3. **Meet the strongest objections.** Reuse a current `understand-challenge` result from the caller, otherwise obtain one. Answer each objection with evidence, concede it or narrow the position. Say what was narrowed and why. Changed position or evidence needs a new challenge. Answering weak objections is a strawman turned around.
4. **Admit weaknesses.** Name objections still standing and thin reasons. Hidden weaknesses are found later at a worse time.
5. **Label the result one-sided.** It is a case for, not a verdict or recommendation. The choice stays with `understand-weigh` or the user. An unlabelled case reads as a recommendation.

For `respond`'s faithful reflection of a view already in the conversation, use a light path: one or two lines that reflect it fairly, with no unsupported new claim. This is not an investigation or researched verdict. The full steps below serve a requested case or work needing evidence.

## Advice

- Lead with a few strong reasons tied to the goal.
- Use known audience concerns to order reasons. Leave an immaterial audience gap unknown.
- Use the best-informed opponent's objections. Independent objections follow `act-verify` rule 2 through `understand-challenge`; reuse its current check.
- Ask whether the position stands if every checkable fact in an objection is true. Check facts, argue interpretation, set rhetoric aside.
- Check forecasts against how often such things succeed. An inside view is often too optimistic.
- Mention a stronger position alongside the requested case, not instead of it. The caller chooses which position to argue.
- Reflect the user's view as they would put it. Check it with them when it matters.
- For `understand-weigh`, give every option equal depth. Effort alone must not make one look stronger.

## Instructions

1. **Give the position through `understand-frame`.** Handle audience by rule 1.
2. **Gather reasons and evidence.** Use `understand-research-fact` for sourced factual checks. Return its result here without restarting the current challenge or choosing for the caller. Mark unchecked reasons as assumptions.
3. **Get the strongest objections through `understand-challenge`.** Reuse a current result by rule 3.
4. **Meet each objection.** Answer, concede or narrow the position.
5. **Admit remaining weaknesses.** Rate the case strong, moderate or weak from its evidence, with why and what would strengthen or break it.
6. **Check the case before returning it.** Include the position, supported or marked reasons, objections met, weaknesses, strength and one-sided label. Apply the `understand` skill's rules.

Use `understand-challenge` for the case against. Use `understand-weigh` for a choice. Use `understand-research-fact` for factual truth. If no honest case exists, show the best found and rate it weak; invent nothing.

Return the position (including any narrowing), goal, constraints and audience; reasons and evidence; objections met; remaining weaknesses; strength and why; next evidence; and the one-sided label. This is a default shape. A direct case request gets the full case. A comparison caller shows its strongest reasons and weaknesses; a reflection uses the light path; a document caller uses it as an argument with weaknesses where readers need them.

Keep no lasting record yourself. Return the chosen option's case and open weaknesses for a keeper to record. Return a current challenge separately to a caller for reuse. Its verdict stays outside the one-sided case.

## The last instruction

Check fidelity to the requested position, evidence and marked assumptions, strong objections, admitted weaknesses, strength and next evidence. Keep the label and choice boundary. Reuse current checks and follow the `understand` skill's rules. A light reflection needs fidelity, not a new investigation.
