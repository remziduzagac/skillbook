# understand-argue

Makes the strongest honest case for a position, labelled one-sided.

## When to use

Use when the user wants the strongest honest case for one position, such as a pitch for a four-day week. Also use the light path when a response needs to reflect an existing view fairly.

## When not

- The case against a position: use the `understand-challenge` guide to find weak points.
- Choosing between positions or debating them: use the `understand-weigh` guide. A one-sided case does not choose a winner.
- The truth of a fact: use the `understand-research-fact` guide for evidence. A strong argument does not prove its facts.
- New options: use the `understand-brainstorm` guide to generate them.
- Writing the persuasive document itself: return it to the main task’s writing work. This guide supplies the case.

## Gives back

The case, evidence, objections answered, remaining weaknesses, strength and what could change it. Label it one-sided. Return the current challenge separately for reuse; its verdict is not part of the case.

## Rules

1. **Give the precise position through the `understand-frame` guide.** Give its claim, goal and constraints. A vague position can be defended against anything and proves nothing.
   - Get the audience from the caller or known context.
   - **If an unknown audience would change the case, ask through the `understand-clarify` guide.** Then end the turn.
   - If the unknown audience would not change the case, mark it unknown. Invent no audience concerns.
2. **Support each reason with evidence or mark it as an assumption.** Give its source, strength and limits. A reason from memory counts as unchecked until a source confirms it. State nothing false or overstated. False premises fail when relied on.
3. **Meet the strongest objections.** Reuse a current the `understand-challenge` guide result from the caller, otherwise obtain one. Answer each objection with evidence, concede it or narrow the position. Say what was narrowed and why. Changed position or evidence needs a new challenge. Answering weak objections is a strawman turned around.
4. **Admit weaknesses.** Name objections still standing and thin reasons. Hidden weaknesses are found later at a worse time.
5. **Label the result one-sided.** It is a case for, not a verdict or recommendation. The choice stays with the `understand-weigh` guide or the user. An unlabelled case reads as a recommendation.

For the `respond` guide's faithful reflection of a view already in the conversation, use a light path: one or two lines that reflect it fairly, with no unsupported new claim. This is not an investigation or researched verdict. The full steps below serve a requested case or work needing evidence.

## Advice

- Lead with a few strong reasons tied to the goal.
- Use known audience concerns to order reasons. Leave the audience unknown if knowing it would not change the case.
- Use the best-informed opponent's objections. Independent objections follow the `act-verify` guide's rule 2 through the `understand-challenge` guide; reuse its current check.
- Ask whether the position stands if every checkable fact in an objection is true. Check facts, argue interpretation, set rhetoric aside.
- Check forecasts against how often such things succeed. Looking only at this one situation can make a forecast too optimistic.
- Mention a stronger position alongside the requested case, not instead of it. The caller chooses which position to argue.
- Reflect the user's view as they would put it. Check it with them when it matters.
- For the `understand-weigh` guide, give every option equal depth. Effort alone must not make one look stronger.

## Instructions

1. To make the position precise, give the position through the `understand-frame` guide. Handle audience by rule 1.
2. To ground the case in evidence, gather reasons and evidence. Use the `understand-research-fact` guide for sourced factual checks. Return its result here without restarting the current challenge or choosing for the caller. Mark unchecked reasons as assumptions.
3. To test the strongest opposition, get the strongest objections through the `understand-challenge` guide. Reuse a current result by rule 3.
4. To make the case honest, meet each objection. Answer, concede or narrow the position.
5. To show how strong the case is, admit remaining weaknesses. Rate the case strong, moderate or weak from its evidence, with why and what would strengthen or break it.
6. To return a complete one-sided case, check the case before returning it. Include the position, supported or marked reasons, objections met, weaknesses, strength and one-sided label. Apply the `understand` guide's rules.

If no honest case exists, show the best found and rate it weak. Invent nothing.

Return the position (including any narrowing), goal, constraints and audience; reasons and evidence; objections met; remaining weaknesses; strength and why; next evidence; and the one-sided label. This is a default shape. A direct case request gets the full case. A comparison caller shows its strongest reasons and weaknesses; a reflection uses the light path; a document caller uses it as an argument with weaknesses where readers need them.

Keep no lasting record yourself. Return the chosen option's case and open weaknesses for the skill that saves records. Return a current challenge separately to a caller for reuse. Its verdict stays outside the one-sided case.

## The last instruction

Check fidelity to the requested position, evidence and marked assumptions, strong objections, admitted weaknesses, strength and next evidence. Keep the label and choice boundary. Reuse current checks and follow the `understand` guide's rules. A light reflection needs fidelity, not a new investigation.
