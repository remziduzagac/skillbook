# coordinate-delegate-council

## Purpose

Collects independent answers to one question and keeps their disagreements, so the user can judge the different views.

Needs: permitted fresh workers through the active call of the `coordinate-delegate` guide. Without them, return the limitation, the missing answers and their next owner. The required independence stays pending.

## When to use

Use when several independent agents should answer the same question from the same material. For example, their different answers may expose disagreements that the user needs to see.

## When not

- Separate reading parts or review angles: use the `coordinate-delegate-fanout` guide. Council members answer the same whole question.
- Separate changes: use the `coordinate-delegate-crew` guide. A council collects answers; it joins no edits.
- A recommendation the user did not ask for: keep the answers and let the user choose. Agreement between members is not a decision.

## Gives back

Each member’s answer with its name, a summary that keeps disagreements, and which answers are missing.

## Rules

1. **Give every member the same question and material.** Leave the main agent's opinion out of the task evidence. Keep the required operating instructions from the `coordinate-brief` guide: removing bias must not remove the worker's authority limits.
2. **Use fresh workers at standard tier or above.** Each answer needs judgment. A fork shares the main agent's reasons and cannot supply independence. Follow the parent's tier and effort rules.
3. **Keep every answer and disagreement accessible to the user.** Attribute each view to its member. Agreement by count does not settle the user's choice.

## Advice

- About three members usually reveal disagreement without unnecessary cost. Mix models or harnesses when their different strengths help. For another harness, follow the `coordinate-delegate` guide's rules on allowed harnesses, approval to send data and cost.

## Instructions

Collect independent answers to the same question, and keep their disagreements available to the user. Comparable material and attributed answers matter more than agreement by count. **Set the common question, brief fresh members through the active delegate call, then return their actual answers and missing work.**

1. **Scope the common question and material under rule 1.** Different questions or evidence make disagreement impossible to interpret.
   - If a gap in the question or material would change the answers, settle it first through the `understand-clarify` guide.
2. **Choose independent members through the active `coordinate-delegate` guide call, by rule 2.** A fork shares the main agent's reasoning and cannot provide the requested independence.
   - Use the parent's mapping, effort, cost approval, controls and tracking. About three members is guidance, not a fixed quota.
   - Follow the parent's harness and data permissions. Restart no method selection, and let no worker delegate again.
3. **Prepare each brief through the `coordinate-brief` guide.** A common question alone does not give a worker its scope or report obligations.
   - Give the same question and material, baseline, success criterion, report and cleanup request to every member.
4. **Collect each member's actual result through the parent's lifecycle.** A started or waiting member is not an answered question.
   - Use its waiting, obstacle, verification and cleanup steps. Keep running, blocked, failed and cancelled states distinct from answers.
5. **Return a summary with each member's answer accessible, by rule 3.** Flattening disagreement into a majority view takes away information the user asked to see.
   - Name missing answers with their known reasons. The user decides or asks for more.
   - Use the `understand-weigh` guide only for a requested recommendation.
6. **Check council results and “Gives back” before returning.** Always do this last. A partial council must not read as a completed set of independent views.
   - Check independence, common material and absence of the main agent's opinion as evidence. Check that every answer is accessible and missing answers are named.
   - Fix misleading summaries or statuses. Return to the active caller with pending checks and next owners, without inventing agreement.
