# coordinate-delegate-council

Collects independent answers to one question and preserves where they disagree.

Needs: permitted fresh workers through the active the `coordinate-delegate` guide call. If unavailable, return the limitation, missing answers and next owner. Required independence stays pending.

## When to use

Use when several independent agents should answer the same question using the same material. For example, their different answers may expose disagreements that the user needs to see.

## When not

- Separate reading parts or review angles: use the `coordinate-delegate-fanout` guide. Council members answer the same whole question.
- Separate changes: use the `coordinate-delegate-crew` guide. Council collects answers rather than joining edits.
- A recommendation the user did not ask for: keep the answers and let the user choose. Agreement between members is not a decision.

## Gives back

Each member’s answer with its name, a summary that keeps disagreements, and which answers are missing.

## Rules

1. **Give every member the same question and material.** Exclude the main agent's opinion from task evidence. Keep the required operating instructions from the `coordinate-brief` guide. Removing bias must not remove the worker's authority limits.
2. **Use fresh workers at standard tier or above.** Each answer needs judgment. A fork shares the main agent's reasons and cannot supply independence. Follow the parent's tier and effort rules.
3. **Keep every answer and disagreement accessible to the user.** Attribute each view to its member. Agreement by count does not settle the user's choice.

## Advice

- About three members usually reveal disagreement without unnecessary cost. Mix models or harnesses when their different strengths help. For another harness, follow the `coordinate-delegate` guide's rules on allowed harnesses, approval to send data and cost.

## Instructions

1. To make answers comparable, scope the question and common material. Follow the shared choice rules for gaps that would change the result.
2. To get independent views within authority, choose the members within the active delegate call. Use the active delegate call's permitted controls, model mapping, approved cost and task tracking. Do not restart the parent's method selection or let a worker start another worker.
3. To give each member enough context, prepare each member's brief through the `coordinate-brief` guide. Include the common question and material, required baseline, scope, success criterion, report and cleanup request.
4. To keep actual work status visible, collect each member's actual result. Follow the parent for waiting, obstacles, verification and cleanup. Keep running, blocked, failed and cancelled states distinct from answered work.
5. To preserve disagreements for the user, return the summary with each answer accessible beside it. Name each member whose answer is missing. Give the reason when it is known. Preserve disagreements. The user decides or asks for more. Use the `understand-weigh` guide only for a requested recommendation.

## The last instruction

Check that members were independent and that no brief supplied the main agent's opinion as evidence. Return the summary and each member's answer to the active caller. Report work that is actually missing. A partial council is not a completed set of independent answers. Report any pending check and its next owner.
