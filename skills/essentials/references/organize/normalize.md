# organize-normalize

Extracts a repeated part into one shared home, preserving item-specific details and meaning.

## When to use

Use when several items repeat a part that should have one shared home and references. A repeated definition may belong in a glossary; shared code may belong in one function.

## When not

- Duplicate whole accounts: use the `organize-merge` guide. Normalize shares one repeated part rather than combining the whole items.

## Gives back

The shared part and working references to it. List copies with different meanings and leave them unchanged.

```text
A[x] B[x] → A[→X] B[→X] X
```

## Instructions

1. To locate the shared content, find the repeated part.
2. To preserve differences in meaning, check that it means the same thing in each eligible item. Similar words are not enough. Leave copies with different meanings unchanged. List those copies as excluded from normalization.
3. To make the shared part reachable, choose one home every eligible reader can reach. A definition may belong in a glossary, a rule in the guide or skill whose scope it covers, or code in a shared function. Follow the parent's shared choice rule. If no home exists, propose one through the `respond-ask` guide. End the turn.
4. To avoid duplicate shared content, prepare the shared part once. Make it general enough for every eligible user and no broader. Write the shared part only after the user approves the `organize` guide's map.
5. To keep every eligible item connected, replace eligible copies with working references under the approved map. Keep item-specific details and meaning. Check each reference reaches the shared part.

## The last instruction

Return the proposal or approved result to the parent. The shared part exists once after applying. Every eligible copy points to it and keeps its meaning. Differing copies remain unchanged and listed. Follow the `organize` guide's inventory check and both approval checkpoints.
